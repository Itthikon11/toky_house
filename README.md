# 🌼 TOKYO HOUSE — ระบบสั่งอาหารร้านขนมโตเกียว

ลูกค้าสแกน QR ที่โต๊ะ → สั่งอาหาร → ออเดอร์เด้งขึ้นแดชบอร์ดของร้านทันที →
สั่งเพิ่มกี่รอบก็ **รวมเป็นบิลเดียว** → **ชำระเงินกับพนักงานเท่านั้น** (ไม่มีการชำระออนไลน์)

- ฝั่งหน้าเว็บ: **React + Vite + Tailwind CSS** (build ออกมาเป็นไฟล์ static)
- หลังบ้าน: **Supabase** (Postgres + Auth + Realtime) — ไม่มีเซิร์ฟเวอร์ของเราเองให้ดูแล ใช้ Free Tier ได้

### ลูกค้า
| ฟีเจอร์ | รายละเอียด |
| --- | --- |

## 🚀 เริ่มใช้งาน (เครื่องตัวเอง)

ต้องมี Node.js 18+ และ pnpm

```bash
pnpm install
pnpm dev
```

เปิด http://localhost:5173

**โหมดทดลอง**: ถ้ายังไม่ได้ตั้งค่า Supabase ระบบจะใช้ข้อมูลตัวอย่างที่เก็บในเบราว์เซอร์
ใช้ดูหน้าตาและทดสอบการทำงานได้ครบ (รหัสพนักงานเริ่มต้น `admin1234`)
แต่ **ข้อมูลไม่แชร์ข้ามเครื่อง** — ลูกค้าสั่งจากมือถือ จอพนักงานในคอมจะไม่เห็น
ใช้งานจริงต้องเชื่อม Supabase ตามขั้นตอนด้านล่าง

ทดลองเป็นลูกค้า: ล็อกอินพนักงาน → หน้า “โต๊ะ & QR” → กด “ทดลองเปิดลิงก์” ของโต๊ะใดก็ได้

## 🔌 เชื่อมต่อ Supabase (ใช้งานจริง)

1. สร้างโปรเจกต์ฟรีที่ https://supabase.com
2. **SQL Editor** → วางไฟล์ [`supabase/schema.sql`](supabase/schema.sql) ทั้งไฟล์ → Run
   (สร้างตาราง, สิทธิ์ RLS, ฟังก์ชันสั่งอาหาร/รวมบิล/เรียกพนักงาน, เปิด Realtime, โต๊ะ 1–12 + เมนูตัวอย่าง)
3. **Authentication → Users → Add user** สร้างบัญชีพนักงาน (อีเมล + รหัสผ่าน)
4. กลับไป **SQL Editor** ให้สิทธิ์พนักงาน (เปลี่ยนอีเมล):
   ```sql
   insert into public.staff_members (user_id, display_name)
   select id, 'เจ้าของร้าน' from auth.users where email = 'owner@example.com'
   on conflict do nothing;
   ```
5. **Authentication → Sign In / Providers** → ปิด “Allow new users to sign up”
   (กันคนนอกสมัครเอง — ถึงสมัครได้ก็ไม่มีสิทธิ์ เพราะไม่อยู่ใน `staff_members`)
6. คัดลอก `.env.example` เป็น `.env` แล้วใส่ค่าจาก **Project Settings → API**
   ```env
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   VITE_PUBLIC_URL=https://โดเมนร้าน.vercel.app
   ```
7. รัน `pnpm dev` ใหม่ → ล็อกอินด้วยอีเมลพนักงาน → หน้า “โต๊ะ & QR” → พิมพ์ QR ไปติดโต๊ะ

## 🌐 นำขึ้นเว็บ (ฟรี)

```bash
pnpm build        # ได้โฟลเดอร์ dist/
pnpm preview      # ทดสอบไฟล์ที่ build แล้ว
```

| Hosting | วิธี |
| --- | --- |
| **Vercel** | Import repo → Framework: Vite → ใส่ Environment Variables เหมือนใน `.env` (มี `vercel.json` ให้แล้ว) |
| **Netlify / Cloudflare Pages** | Build command `pnpm build`, Publish `dist` (มี `public/_redirects` และ `public/_headers` ให้แล้ว) |
| **GitHub Pages** | อัปโหลด `dist/` (build จะสร้าง `404.html` ให้ลิงก์ QR ทำงาน) |

> ⚠️ ต้องตั้ง `VITE_PUBLIC_URL` เป็นโดเมนจริง **ก่อนพิมพ์ QR** ไม่อย่างนั้น QR จะชี้ไปที่ localhost

## 🔒 ระบบป้องกัน

| ความเสี่ยง | การป้องกัน |
| --- | --- |
| คนนอกร้านสั่งอาหารแกล้ง | ต้องมี **token ลับของโต๊ะ** จาก QR (สุ่ม 96 บิต) เดาเลขโต๊ะไม่ได้ · เปลี่ยนรหัส QR ได้ทันที · session โต๊ะหมดอายุใน 4 ชม. |
| แก้ราคาจากเครื่องลูกค้า | ราคา/ชื่อเมนูคำนวณใหม่จากฐานข้อมูลทุกครั้ง (`place_order`) ส่งไปแค่รหัสเมนู + จำนวน |
| สั่งเมนูที่หมด / จำนวนผิดปกติ | ตรวจที่ฐานข้อมูล: เมนูต้องเปิดขาย, 1–20 ชิ้นต่อรายการ, ไม่เกิน 30 รายการต่อรอบ |
| กดสั่งรัว ๆ / ส่งซ้ำ | จำกัด 3 ออเดอร์ / 30 วินาที / โต๊ะ · `client_key` กันออเดอร์ซ้ำเมื่อกดซ้ำหรือเน็ตหลุด |
| กดเรียกพนักงานรัว ๆ | กดซ้ำได้ทุก 60 วินาที · ถ้ายังไม่มีคนรับจะนับเป็น “เรียกซ้ำ n ครั้ง” ไม่สร้างรายการใหม่ |
| ลูกค้าดูบิลโต๊ะอื่น / ปิดบิลเอง | ลูกค้า (anon) **อ่าน/เขียนตารางตรง ๆ ไม่ได้** (RLS) เรียกได้เฉพาะฟังก์ชันที่กำหนด · ปิดบิลได้เฉพาะพนักงาน |
| บิลซ้อน / สองเครื่องสั่งพร้อมกัน | ล็อกทีละโต๊ะ (`pg_advisory_xact_lock`) + unique index “1 โต๊ะ 1 บิลที่เปิดอยู่” |
| แก้บิลที่ชำระแล้ว | trigger `guard_closed_bill` ห้ามเปลี่ยนสถานะ/วิธีชำระของบิลที่ปิดแล้ว |
| เดารหัสพนักงาน | Supabase Auth + ต้องอยู่ใน `staff_members` · ล็อก 5 นาทีเมื่อผิด 5 ครั้ง · session หมดอายุ |
| XSS / Clickjacking / CSV injection | React/`textContent` escape ทุกข้อความ · CSP ตอน build · `X-Frame-Options: DENY` · escape ค่า CSV |

> โหมดทดลอง (ไม่มี Supabase) ทุกอย่างอยู่ในเบราว์เซอร์ จึง **ไม่ปลอดภัยสำหรับใช้งานจริง** —
> ใช้เพื่อทดสอบเท่านั้น (รหัสผ่านเก็บเป็น SHA-256 ผ่าน `pnpm hash-password "รหัสใหม่"`)

## 💸 ประหยัดค่าใช้จ่าย (Supabase Free Tier)

- **ไม่มีเซิร์ฟเวอร์รันตลอดเวลา** — หน้าเว็บเป็นไฟล์ static, ตรรกะสำคัญอยู่ในฟังก์ชัน Postgres
- **Realtime ช่องทางเดียว** ต่อหน้าจอพนักงาน (รวม bills/orders/staff_calls ใน channel เดียว, จำกัด 5 event/วินาที)
- ฝั่งลูกค้า **ไม่ใช้ Realtime** — ดึงสถานะบิลทุก 10 วินาทีเฉพาะตอนเปิดหน้าอยู่ (หยุดเมื่อสลับแอป)
- Polling ของพนักงานเป็นแค่ตัวสำรองทุก 30 วินาที เผื่อ Realtime หลุด
- หน้าพนักงาน (กราฟ, QR) แยกโหลดทีหลัง ลูกค้าไม่ต้องโหลด

> Supabase Free จะ **หยุดโปรเจกต์ชั่วคราวถ้าไม่มีการใช้งาน 7 วัน** — เปิดใช้ทุกวันตามปกติไม่มีปัญหา

## 🎨 Design System (UX/UI)

ทุกหน้าใช้ชุดส่วนประกอบเดียวกัน — **ห้ามแต่งสี/ปุ่มเองทีละหน้า** ให้ใช้ของที่มีอยู่

| ส่วน | ใช้ที่ | หมายเหตุ |
| --- | --- | --- |
| สี / ฟอนต์ / เงา | `tailwind.config.js` | `brand-yellow` = สีหลัก, `brand-ink` = ตัวอักษร/ปุ่มรอง |
| class มาตรฐาน | `src/styles/index.css` | `.btn-*` `.input` `.badge-*` `.chip` `.card` `.callout-*` `.page` |
| ปุ่ม | `<Button variant size icon loading block to>` | สูงอย่างน้อย 44px (กดง่ายบนมือถือ) มีสถานะกำลังโหลดในตัว |
| ไอคอน | `<Icon name="bell" />` (`src/lib/icons.js`) | SVG ชุดเดียวทั้งแอป — ไม่ใช้อีโมจิ (แต่ละเครื่องแสดงไม่เหมือนกัน) |
| สถานะ | `<StatusBadge kind="order\|bill" status>` | สี/ไอคอน/ข้อความมาจาก `config/constants.js` ที่เดียว |
| อื่น ๆ | `Modal` (มือถือเป็น bottom sheet) · `Toast` · `EmptyState` · `QtyStepper` · `Switch` · `PageHeader` · `Spinner` | |

**หลักการที่ใช้**
- **มือถือมาก่อน**: ลูกค้าที่สแกน QR มีแถบเมนูล่าง (เมนู · ตะกร้า · บิล · เรียกพนักงาน) กดได้ด้วยนิ้วโป้ง
- **ลดขั้นตอน**: กด + บนการ์ดแล้วปรับจำนวนได้ทันที · ปุ่ม “ขอชำระเงิน” อยู่ในหน้าบิล · ปิด/เปิดขายเมนูกดสวิตช์เดียว
- **บอกสถานะเสมอ**: ทุกปุ่มที่รอเซิร์ฟเวอร์มี spinner · ทุกหน้ามีสถานะโหลด / ว่าง / ผิดพลาด พร้อมบอกว่าต้องทำอะไรต่อ · แจ้งเมื่ออินเทอร์เน็ตหลุด
- **เข้าถึงได้**: ตัวอักษรรองใช้สีเทาเข้มพออ่าน · กรอบโฟกัสชัดเมื่อใช้คีย์บอร์ด · ช่องกรอกมี label · รองรับ “ลดการเคลื่อนไหว” ของระบบ
- **Tailwind**: เขียนชื่อ class เต็ม ๆ เสมอ (เช่น `'badge-danger'`) ห้ามต่อสตริง `badge-${tone}` เพราะ build จะตัด class ทิ้ง

## 🧭 ลำดับการทำงาน

```
ลูกค้าสแกน QR ──► /t/<token> ──► get_table_info ──► เมนู ──► ตะกร้า ──► place_order
                                                                         │
                     มีบิลค้างของโต๊ะนี้? ── ใช่ ──► เพิ่ม “รอบใหม่” ในบิลเดิม ◄┘
                                          └ ไม่ ──► เปิดบิลใหม่
                                                        │ Realtime
                                  แดชบอร์ด ◄────┘  (คิวออเดอร์เด้ง + เสียง)

ลูกค้ากด 🙋 “ขอชำระเงิน” ──► call_staff ──► จอพนักงานแจ้งเตือน “โต๊ะที่ 03”
พนักงานไปที่โต๊ะ รับเงิน ──► กด “รับชำระ” (close_bill) ──► บิลปิด · สแกนครั้งต่อไปเริ่มบิลใหม่
```
